# 本机成绩与幽灵：只报告实际保存结果

结算分开显示成绩与最快幽灵的写入回执；临时读写失败时保留本次完成快照，用“重试本机保存”只重试失败项。保存成功只表示当前浏览器的 Storage 调用成功，不承诺断电耐久、跨设备同步或两个键的原子提交。

## 来源与接缝

复用 [a1dbv 已审自包含模块](https://github.com/dbvv1/a1dbv/tree/837835fc6d4a34e1ef5c59ddff749620375a4f63/experiments/local-race-save)，MIT 许可完整保在 `local-race-save.mjs` 的打包许可注释中。模块正文保持原 SHA-256 `1d53967731cc8b7c8f6d13a22be1a683ae5ae7f87d8ae4b079820539ab4bcd41`，不是新存档系统。

- `build.mjs` 导入模块；`ranking.js` 创建唯一存储所有者，列表读取失败不再显示“还没有成绩”。
- `race.js::finish` 保原防重复，在公路清空上传对象前捕获成绩、名字与幽灵数组副本；先保存，再完成原结算，最后显示回执。昵称保原 `star-rush-name` 读取与“本机车手”默认值，不改成车库档案名；DNF 不写两项。
- `race-features.js` 通过同一所有者读取幽灵；坏数据／读取失败时本局不显示幽灵并提示，移除原来的第二处幽灵写入。
- `ranking.js` 的重试不调用玩法 `finish()`，不重新取名字、赛道或当前采样。成功键不重写；同 ID／相同成绩去重；原最佳更快时保留原幽灵。开始／返回菜单／换赛道时丢弃旧重试快照。
- 旧街机上传的状态只报告网络结果；本机回执只由结算说明维护，避免后续重试成功仍残留第二份旧失败文案。晚到的上传响应也不能改下一局结果。

## 保留与限制

`road-v2`、旧街机与 `road-v1` 的键、最近 100 条记录和按赛道最快幽灵规则不变，不迁移／清空旧数据。坏 JSON 或无效结构保原字节；`invalid-data`、`invalid-input`、`id-conflict` 不提供盲目重试按钮。最远距离、积分、设置、昵称、涂装与音量仍走原路径，不在此保存回执覆盖内。

当前只支持同一来源内一个活动写入者；没有多标签写锁、跨键回滚或长期去重账本。结果回执不随低高度屏幕的介绍文字一起隐藏，结果区可滚动。Node 的真实客户端消费者测试使用受控完成状态和 Canvas／音频／网络 stub，与下列浏览器观察分开。

## 实际界面观察

2026-10-27，既有云端 Chromium 的 Canvas 兼容路径，使用正式菜单的“观看试驾”自然跑完训练场 904m；未改模拟状态、游戏时钟或完赛条件。正常圈显示成绩／幽灵分别保存成功；进入下一局后本机榜可读该成绩。

另一个显式标注的测试页面仅让公路成绩键的 `Storage.setItem` 抛出受控异常，幽灵键不拦截。真实完赛显示“成绩未保存”但“幽灵已保存”；故障未恢复时点击重试仍保失败。恢复测试存储，再点击产品“重试本机保存”，回执转成功、按钮隐藏；“再跑一次”正常重置，重新加载无故障的原页面后本机榜保留两条成绩。不是模拟磁盘满或断电。

独立新读者发现原回执虽可滚动到达，却在短屏完赛首屏不可见；修正为**同一回执与重试入口放在标题之后、统计之前**，失败用原粉色系左边与淡底区别。新读者在实际原生短窗口（约 566px 内容高）正常一圈复验：不滚动即可看见失败与重试，恢复后成功文字可见且失败样式／重试消失；统计、排行、昵称与再跑仍可滚达。不是缩放或注入 CSS 的布局测试。

界面观察对应 `af0ea89`；随后 `0a40a91` 仅恢复原昵称读取来源，以两模式的真实客户端消费者回归验证，不重复跑圈。整条浏览器观察使用 Canvas 自动试驾，不是人工驾驶、Three 恢复证明或性能测试；未验证真实手机触控、屏幕阅读器、远程在线上传或断电耐久。独立操作原始整桌面证据含内部环境信息，不作为公开配图；旧位置图片不再用于说明当前界面。
