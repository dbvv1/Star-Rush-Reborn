# 汐见街屋：现有空间旁置中的独立接线

入口仍为 `?environment=coast-space-v1`。这不是第四个候选，不恢复已取消的整套材质任务，不改变默认、旧街机、其它赛道、车辆、道路、护栏、碰撞、相机或灯光。当前为本地准备代码，尚未发布；真实浏览器最小门槛与正式 WebGL2 同机位图仍待核验，不据 CPU 通过宣称画面改善。

## 来源与放置

- 固定源来自 `ab2655930996b9d81f5fb35469669c72b7be28e1` 的 content-set 输出，沿用 [placement 合同](../authoring/coast-street-placement/README.md)：Kenney City Kit Suburban 2.0，CC0；`house-a`、`house-g`、`house-m` 共 3317 三角面。固定 GLB SHA-256 为 `a542129fdc374200f2cf78ec46b2c811dd7f7e3d8c3167003be4aaa73637c958`。
- 构建先执行 `verifyFixedSource()`，核对 GLB、manifest、上游 adapter、道路样本、许可与各 part 网格哈希，再把原 GLB 字节内嵌到公路包。只有打开空间候选并构建汐见场景才解码、规划与创建网格。旧街机包不含 GLB 字节。没有运行时网络下载或第二份资产转换。
- `coast-street-runtime.mjs` 直接调用已接收的 `planStreetRows`，每 40 m 一排、中心 320–680 m、两侧、setback 4 m、足印间距 0.5 m。20 排中接受 10 排/30 栋：320–600 的 +1 侧，640/680 的 -1 侧。其余 10 排仍整排拒绝；不删单栋、挪动或缩放来凑数。
- 每栋源顶点、法线、线性色与索引不变。原放置矩阵直接用于 Node，只减去 chunk origin；不再次叠加 source pivot。Three 仍由原 Lambert/Toon 顶点色路径消费，不宣称已消费 GLB 的 PBR roughness 元数据。
- 在适配器原 1 m 局部道路净空检查之外，运行接线再检查完整闭环道路样本，防止侵入另一段道路。

## 地基与旧物替换

保留房屋底心在各自道路站位的原高度，不改地形。每栋独立基础使用同一个已接收 XZ 凸足印，顶面精确接房底；底面低于足印 AABB 所覆盖的所有地形网格单元顶点最小高度 0.15 m，保证埋入地形。该范围检查也界定线性地形三角形内部，不仅抽几个点。若任一基础超出地形或地形高过房底，整个空间候选失败回退，不能把失败排偷偷丢掉。

300–710 m 的旧程序住宅/商铺由新街屋替换；原空间候选的三栋额外程序楼也移除。只删除实际世界 AABB 与新基础足印 AABB 相交（含 0.5 m 余量）的旧樱树/松树，保留不冲突的路灯、路牌和其它布景，以及远处 beacon/pine。原随机调用次数不变。

替换仅在整块候选构建成功后提交。每块保留原节点顺序；中途任何空间初始化/装饰失败会移除已有候选节点、恢复所有已缓存块的原节点、释放街屋/基础网格并重建默认地形。

## 两个渲染消费端

- **Three**：共享三个原房屋 Mesh，30 个原矩阵实例。每栋基础是单独小网格，随同一 chunk 渲染。未改材质、阴影、光照或相机。
- **Canvas2D**：仅标记的街屋/基础走新增的实际网格投影，使用原索引、顶点色、世界矩阵，按几何三角绕序（不是平滑着色法线）、视域与近面规则裁去不可见面。候选每 5 m 道路段作为整体，保留原四边形、路肩→路面→标线→护栏的内部画序，以及原路段先后顺序；按深度将街屋面穿插到完整路段之间，避免把路肩和路面三角各自排序形成锯齿缺口；不按任意栋数上限丢弃接收排。同段原简化房屋/树图标停画。它仍是 painter 兼容路径，没有真实地形、阴影或 Three 材质受光，不能代替正式 WebGL2 品质图。
- 关闭候选时，Canvas 原图标、绘制顺序与其它赛道保持原样。

## 验证范围

新增 `tests/coast-street-runtime.test.mjs` 检查固定字节、完整排筛选、实际 Node 变换与网格、基础接地、全环净空、关闭/其它模式惰性、故障恢复、真实 Three 几何/材质/实例消费（仅 GPU renderer stub）、Canvas 实际三角面与完整绘制分支。原 `coastal-space.test.mjs` 的旧节点前缀约束改为明确的替换与逐节点恢复合同，未删除原默认/地形/RNG 检查。

运行：

```sh
npm run build
npm test
node --test authoring/coast-street-placement/test.mjs authoring/coast-street-layout/test.mjs
node tests/side-release-client.mjs
```

这些 CPU/构建检查不启动浏览器或 GPU，也不是正常游玩的画面/性能结论。实际浏览器默认/空间/轮胎/组合各推进至少 600 个物理 tick 的旁置门槛，以及正式 WebGL2 机位/人工判断，应分别记账。

本次准备代码的实际 CPU 结果：完整 `npm test` 通过（188 项单测及后续客户端、三赛道、API、构建变体）；placement/layout 作者测试 59/59；六路各 600 物理 tick 的客户端消费者均无错误。六路玩家状态 hash 均与确切父版 `a9e8181c719a85cec72d5ced6fccfdcf7ab1c099` 相同；三个赛道的公路/旧街机默认场景全部块的几何、矩阵与随机调用次数也逐字节一致。GPU renderer 为 stub 的 Three 测试与 Canvas 命令测试只算 CPU 消费验证。首次构建缺少本工作副本的 Rapier 子目录依赖，复用已有依赖后重跑通过。接入独审发现并修复了以平滑顶点法线剔背面的错误；真实三栋源的六个驾驶视角逐面集合回归证明当前与几何绕序一致，源法线保留。真实浏览器、正式 WebGL2 图像、感知改善及目标设备性能未由这些结果证明。

随后浏览器检查发现了道路路肩/路面拆三角排序造成的明显锯齿覆盖，已改为保留每段原四边形和全部道路先后画序，再与街屋队列保序合并。实际 `drawSoftware` 的七个真实弯道视角覆盖回归已通过；独立 CPU 深度核对的 4449 个道路内侧点和 7107 个道路/街屋遮挡点未发现错误分类。修前实现会在同一回归的 298 m 近场失败。修后真实浏览器仍需重新检查，不能沿用修前截图作为通过证据。
