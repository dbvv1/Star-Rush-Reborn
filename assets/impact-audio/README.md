# 护栏轻／中碰撞：可接手音频 v2

## 规格与来源

- 目标：在既有护栏碰撞反馈事件上接入短金属瞬态，不替换发动机、轮胎、风、喷射或音乐。仅资源分层，不调驾驶／碰撞物理。
- 来源：[Kenney Impact Sounds](https://kenney.nl/assets/impact-sounds)，官方1.0包，2026-10-24重新获取。包内 `License.txt` 原样保留为 `LICENSE-Kenney.txt`，明确 CC0；不是AI生成，也不把创作者商标归入CC0。
- 官方下载：`https://kenney.nl/media/pages/assets/impact-sounds/87b4ddecda-1677589768/kenney_impact-sounds.zip`。
- 原包SHA-256：`029d734af1582474edf3a694d1b0cebc97c1c152f2f39fa34d4c2bafc5de77f8`。不将整包送入运行版本。
- 4个原OGG候选及逐文件hash、解码规格见 `source/`、`candidate-metadata.json`；原许可原文随源交付。

## 实际制作与规格二改

先实际运行了单档v1原型：两个强度都选light，load/play窄断言通过。随后把事件选择改成v2轻／中分层，按既有碰撞反馈的 `impact > 5` 强事件界线选medium，其余有效护栏碰撞选light；不是听后改善，也未调整原0.7触发阈值和160ms碰撞冷却。v2测试验证5/5.01边界、实际两档状态与不同文件引用。

`python3 prepare-impact-audio.py` 用现有ffmpeg将选中OGG处理成单声道22050Hz PCM16 WAV，固定0.5缩放，剥离元数据；命令与源hash可复做。两个运行WAV共28,394字节，解码内存约56.7KB（float32），无需安装依赖即可普通build，只有重做衍生需要ffmpeg。WAV较OGG稍大，但这两短片总量小且原生解码兼容性明确；不在本轮引入转码服务。

## 接入、加载与打包

- 首次现有音频初始化时异步获取同源哈希URL；不阻塞开赛，解码成功才可播放。文件/HTTP/解码/超时失败或尚未ready，**本次碰撞立即走原程序化回退**，不在加载后补播旧事件。
- 每个事件选一个样本，不叠加原护栏噪声；其他碰撞保留程序化。暂定样本gain=0.15，经原SFX master与compressor，服从原音效音量／静音；该保守默认待最终混音听验确定。
- 每次创建独立BufferSource，最多4声部，先结束最旧声部；ended断连。暂停／非running／静音／SFX音量0时清除样本声部。生命周期取消后不可复活加载结果；声音仅自然短尾，无循环。
- 现有F2诊断追加 `rail ready/ready | light/medium #次数`（或fallback），用于接收端确认资源链，不表示声音听验通过。
- build只允许两个命名PCM、校验格式/体积/hash，输出静态文件及现有Worker精确路径；GET/HEAD、audio/wav、immutable缓存，未知／源文件404、其他方法405。引擎代码、原房屋本地待验修改不包含于本版本。

## 本次运行核验

2026-10-24 原授权原生浏览器、正常1188×848窗口、Canvas兼容路径：正常开赛后F2实际显示 `rail ready/ready | none #0`；一次W+A持续1200ms后，18.1m左贴栏画面显示 `rail ready/ready | light #2`，随后出现暂停覆盖。仅证明该运行版本两资源解码及轻碰样本触发链；未扩大为中档实战、连续驾驶或听验通过。自己的预览服务核验后已停止。

## 接收动作与未验项

显式运行 `STAR_RUSH_RAIL_SOURCE=kenney npm run build && npm run dev`，进入驾驶练习（首次用户手势启用音频），F2核两资源ready；在可持续输入端分别产生轻与中护栏碰撞，观察诊断档位与计数。然后在**发动机＋轮胎＋音乐最终混音**中比较两档：弱碰辨识、连续擦碰疲劳、音量与峰值、静音/暂停/重开清理，以及资源404/离线时程序化回退。按听到的问题替换候选或改明确混音参数，再做相同事件复验。

本次没有可消费的实际声音返回，**最终混音试听、听后二改与玩家品质未验**；数值、decode、调用计数和离线测试不充听验。AI音频生成工具未连接，AI生成欠项独立保留。未部署，不以本音频制作完成代替完整主弯驾驶、WebGL或短视口验收。

## 可修改替代：程序合成候选

另接收[本项目确定性合成候选](candidates/synth-v1/README.md)，保留原配方和源字节。master默认原程序音、不加载样本；显式 `STAR_RUSH_RAIL_SOURCE=kenney npm run build` 可选Kenney，播放/混音参数不变；显式作者构建 `STAR_RUSH_RAIL_SOURCE=synth-v1 npm run build` 才使用替代两片，未知值失败。用同一运行链比较素材而非同时改变混音，听后用 `STAR_RUSH_RAIL_SOURCE=procedural npm run build` 恢复默认。该候选不是CC0或AI生成，许可边界与待听动作见该记录。
