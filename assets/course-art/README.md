# 赛道选卡插画：窄资源链

三张原创 AI 插画仅供大厅选卡装饰，不是实机截图，不替代赛道 SVG、标题、难度或选中状态；不用于赛中方向标识。v1 已在实际云端浏览器看见并完成三赛道选择、练习自动选训练、进赛和返回；海岸缩图辨识不够，真正编辑图片形成 coast-v2，花见／训练保留 v1。海岸 v2 已在相同 1188×761 兼容模式大厅复验：蓝绿水面和岸线更明确，路线轮廓、标题和选中框保持可读；这不是驾驶收益或赛中 WebGL 资产验收。

## 来源与许可边界

2026-10-23 使用 OpenAI 内置 `image_gen`，工具未公开具体模型快照，不推断型号。无第三方图片输入；海岸为原创首图，樱花／训练图仅以海岸图作风格与构图参考，不算同一资产的需求二改。原始输出文件名、项目内 PNG／WebP、SHA-256、参考母版和提示词关系逐件记录在 `manifest.json`；完整原提示词在 `PROMPTS.md`。

生成服务输出不是 CC0 现成素材。公开 [OpenAI Terms of Use](https://openai.com/policies/terms-of-use/) 说明输出归属以适用法律和用户实际合同为条件，且不保证独特性；本记录不声称版权独占或第三方权利担保。未使用商标、真人、指定艺术家或商业游戏素材。选型时比较过 CC0 的 [Kenney Racing Pack](https://kenney.nl/assets/racing-pack) 和 [Background Elements Remastered](https://kenney.nl/assets/background-elements-remastered)：俯视瓦片／通用欧式场景组件不直接匹配三条日式赛道的环境身份，语义路线仍保程序化。

## 处理与构建

PNG 为 1774×887 的可二改母版；只缩放和编码，不手工涂绘。用 Pillow 12.3.0 验证：

```bash
# 仅在重新制作图片时需要 Pillow；普通构建／运行不需要。
python3 -m pip install Pillow==12.3.0
python3 prepare-course-art.py
python3 tests/course-art-processing.py
npm run build
npm test
```

处理配方：保持完整 2:1 画面 → RGB → 最大 512×256 的 Lanczos 缩图（不放大）→ WebP quality=82、method=6。改源时新增版本文件，更新 manifest 的输出、源、哈希、revises 和对应提示词，不覆盖批准母版。当前选中衍生总大小 40,588 字节；海岸旧 v1 衍生和全部 PNG／来源记录保留项目源、不进运行包。

构建仅接收三条已知赛道的、每张不超过 180 KB、由该配方输出的简单 VP8 WebP；缺失文件、非法清单、错误 RIFF 长度、缺失／截断图像块和超预算输入使构建失败。这是基础容器校验，不承诺识别所有压缩数据损坏；实际资源还须解码和呈现验收。内容哈希进入同源 URL，选中的图片复制到 `dist/client/assets/course-art/`，并嵌入现有 Worker 的精确资源路由，故不依赖外部图床或额外静态托管。图片返回 `image/webp`、长期 immutable 缓存；新内容换哈希 URL。源 PNG、manifest 和提示词没有公开 HTTP 路由。

## 运行与验收

图片按原 2:1 比例放在卡上部，底部渐隐，SVG 路线保留原位置、尺寸、路径及开始点。加载不阻塞选卡；失败移除装饰图，回原色底；不增加可聚焦元素或改变按钮名称。

离线测试分别覆盖加载／失败生命周期、缺失／非法／超预算构建输入、Worker 字节与 MIME／缓存／GET／HEAD／405／404，以及既有驾驶、HUD、房间和排行榜回归。DOM 手动 load/error 事件仅为单元测试，不是实际浏览器成功加载证据。

真实 UI 已验：三图显示、路线和名称清楚；海岸→花见→训练／练习模式切换保持原语义、能进赛并返回；正常重新打开后海岸新版显示。尚未完成本插画版的窄屏／短屏、真实网络失败 UI 和发布端验收。图片失败目前只在离线生命周期测试中验证，不注入假状态冒充浏览器验证。

本次第二次需求要求“保海岸身份和路线净空，让小卡更容易认出海”。对已接入海岸 v1 做真正图片编辑后重新处理／打包，在同一布局、同一 CSS 下对照 v2；没有用 CSS 透明度冒充图片二改。此窄案例通过，不推广为任意资产零返工；未来缩图后主题仍不可辨或抢路线，就撤回插画，保留已合格原卡。
