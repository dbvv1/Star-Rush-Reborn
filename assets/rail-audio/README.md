# 护栏碰撞音频：两份可替换候选

这是护栏轻擦／中等撞击的两份短 WAV 候选和窄接入记录，不是完整音频质量验收。声音由本仓库的 Python 标准库脚本按固定参数、固定种子程序合成；没有下载第三方采样，没有调用托管 AI 音频生成服务，也没有声称人耳试听已通过。

## 候选与体积

| 候选 | 文件 | 时长 | 帧数 | 体积 | SHA-256 前 12 位 | 目标峰值 |
| --- | --- | ---: | ---: | ---: | --- | ---: |
| 护栏轻擦 | [rail-light-v1.wav](rail-light-v1.wav) | 0.240000 s | 10,584 | 21,212 B | `6186d2d5ad2f` | 0.78 |
| 中等撞击 | [rail-hit-v1.wav](rail-hit-v1.wav) | 0.380000 s | 16,758 | 33,560 B | `951531290357` | 0.86 |

两份合计 54,772 B。格式均为单声道、44.1 kHz、16-bit PCM WAV，44 字节标准 PCM 头。`rail-light-v1.wav` 实测整段峰值 0.78、RMS 0.0852；`rail-hit-v1.wav` 峰值 0.86、RMS 0.1622。RMS 只是离线数值，不代表主观响度或游戏内混音平衡。

## 来源、参数与许可

- 来源：`generate.py` 的确定性模态／噪声合成。轻擦使用约 63 Hz 颗粒调制的带限噪声、1640/2470/3890 Hz 衰减模态与短促高频 onset；中等撞击使用 118→62 Hz 下滑低频 body、带限噪声、420/930/1710/2570 Hz 模态和 onset。
- 可复现源：`generate.py` 的 `RECIPES` 保存随机种子、目标峰值、包络、截止频率、模态增益／衰减／相位等全部参数；`manifest.json` 也逐项保留参数、SHA-256、字节数、帧数和时长。脚本无时间戳、无系统随机数，同一 Python 运行时／平台重复运行应得到逐字节相同结果，`--check` 和测试会守护当前清单。
- 许可：原创代码合成，未使用第三方录音、采样库或生成服务；随本仓库现有源码条款分发，不额外声明 CC0／公有领域，也不作版权登记或独占性保证。未做独立法律审查。

## 接入与混音规则

真实事件链是 `circuit.js` 的 `collisionFeedback(impact, kind)` → `impactSound(kind, impact)`；第二参数是接触法向强度，不是车速。只有 `kind === 'rail'` 会尝试素材分支。素材按强度（夹在 0.7–10）选择／混合：

- `< 2`：只播放轻擦；
- `2–6`：轻擦与中等撞击按等功率曲线 `cos/sin` 交叉淡化；
- `> 6`：只播放中等撞击；
- 总播放增益为 `clamp(0.045 + impact × 0.022, 0.06, 0.30)`，再进入现有 `master`/压缩器总线和既有音效音量、静音控制。

所有输入均做有限值、上下界夹取。素材未加载、请求失败或解码失败时，`impactSound` 继续使用原有程序化 band-pass 噪声＋三角波护栏声；素材成功开始播放后立即返回，不再叠加原护栏声。其它碰撞类型、发动机、轮胎、风噪、喷射和音乐路径不变。当前选择逻辑是离线调校，尚未根据真人试听或实机音量重新拟合。

## 构建、修改与验证

声音再生成只用 Python 3 标准库；普通构建沿用仓库现有 Node.js 与 Python 环境：

```bash
npm ci
python3 assets/rail-audio/generate.py --check
npm run build
npm test
```

修改声音时编辑 `generate.py` 的 `RECIPES`，运行 `python3 assets/rail-audio/generate.py` 重新生成两个 WAV 和 `manifest.json`，再执行构建。构建只接受 `light-scrape`／`medium-hit` 两个固定键、对应 `rail-light-vN.wav`／`rail-hit-vN.wav` 文件名、44.1 kHz 单声道 16-bit PCM、0.12–0.5 s、单文件不超过 96,000 B 且清单哈希／字节数／帧数／时长一致的文件。缺失文件、非法清单、错误容器或 PCM 参数、截断数据和哈希不符会使构建失败。内容哈希进入 `/assets/rail-audio/` URL；构建把选中的 WAV 写入 `dist/client/` 并嵌入现有 Worker 精确资源表，返回 `audio/wav`、长期 immutable 缓存。普通 HTTP 不暴露 `manifest.json` 或生成脚本。

`tests/rail-audio.mjs` 覆盖：真实 `resolveContacts`／`collisionFeedback` → `impactSound` 护栏分支（车轴和接触强度用测试替身驱动，不冒充完整驾驶物理）；未加载时回退；加载后按强度单发／等功率双发且不叠原声；静音／总音量和非护栏路径；fetch／decode 失败回退；构建后字节、MIME、缓存、GET／HEAD／405／404；清单哈希与重生成确定性；构建缺失／损坏输入。

## 已验证的浏览器解码与待接收项

- **未做人耳试听**：未评价音色是否像金属护栏、轻／中强度是否自然、重复碰撞是否疲劳，也未与发动机／音乐做主观掩蔽和响度平衡。
- **真实浏览器解码已验**：2026-10-25（UTC+8），本机隔离 Edge 155.0.4283.62 打开未经修改的普通预览，通过产线 Worker 同源 URL 取得两份 WAV，均为 HTTP 200／`audio/wav`，使用真实 `AudioContext.decodeAudioData` 解码为非零、有限样本，时长分别为 0.24／0.38 秒，页面无脚本错误。浏览器在 48 kHz 上解码 44.1 kHz 源文件；实际结果见 [浏览器解码记录](browser-decode-check.json)。这项检查读取实际构建文件，不是替身解码，也不等同真实碰撞时机或听感验收。
- **实际混音录音未验**：本次没有取得真实游戏混音片段，也没有人耳试听；保留原始候选交接收者继续试听。源码集成测试中的 `AudioContext` 仍为替身，其证明范围与上述浏览器解码分别记录。
- **未做发布端验收**：未在生产域名、移动设备、不同采样率／音频输出设备上验证加载延迟、缓存、并发多声部、自动播放策略和实际音量。
- **未做真人碰撞时机验收**：测试中的 `impact=4` 等值是合成输入，不代表真实驾驶中撞击强度分布；等功率交叉区间的听感仍需接收者用真实比赛调整。

以上项目需要接收者在普通浏览器/生产预览中实际触发护栏碰撞、反复试听两份候选并保留真实录音或明确的人工听感结论后，才能宣称最终混音通过。
