# 车辆标准件 CPU 接线核查（B-STAR-CAR-STANDARD-READER-20261104）

**结论先说：** 在固定源 `ab265593` 的 `car.glb`／`manifest.json`／`adapter.mjs` 上，用当前
`engine.js` 的原 `Mesh`／`Node`／`mm`／`ry`／`rz`／`trs` 路径，可以把五件车（`body`＋四轮）
接到当前 `player.roadSteer`／`wheelSpin`／`roll`／`bob`，直行、右弯、左弯、复位四态都得到
确定性的节点矩阵，四轮解析触地点都在 `y≈0`（浮点残差 `-1.4e-8 m`），前轮转向、后轮不转，
复位后 `body` 为单位矩阵、四轮为各自 pivot 平移。

**但这不等于可以直接替换。** 外观轴距（源声明 `±0.858 m`，轴距 `1.716 m`）与当前物理轴距
（`+1.06 / -1.02 m`，轴距 `2.08 m`）相差 `0.364 m`；视觉轮距（轮胎中心 `±0.5525 m`，`1.105 m`）
与当前 `±0.83 m`／`1.66 m` 相差 `0.555 m`。按原 pivot 接线时四轮自己贴地，若把标准轮塞进
当前 `x=-1.02/+1.06、y=0.41、z=±0.83` 的旧轮位，才会出现 2 cm 悬浮／2 cm 入地。**不能调物理、
碰撞或镜头去迁就外观**；新车是否采用、追尾机位是否遮挡、手感如何，留 dot 判断。

本卡只做 CPU 与文件处理：未开浏览器（含 headless）、未用 GPU、未操作桌面／键鼠、未装软件、
未访问网络或模型网关。运行环境 Node `v22.23.2`（仓库要求 Node 24；**未在 Node 24 复跑**）。

## 4. 外观轴距与物理轴距（必须分开）

| 项目 | 当前物理／旧表现 | 标准件外观 | 差 |
|---|---:|---:|---:|
| 前轴位置 | `+1.06 m`（`RoadVehicleModel.config.frontAxle`，`racer.js` 前轮 `x=1.06`） | `+0.858 m` | 物理轴比外观轴前移 `0.202 m` |
| 后轴位置 | `-1.02 m`（`rearAxle=1.02` 取反；`racer.js` 后轮 `x=-1.02`） | `-0.858 m` | 物理后轴比外观后轴更靠后 `0.162 m`（坐标差 `-0.162 m`） |
| 轴距 | `2.08 m` | `1.716 m` | 物理轴距长 `0.364 m`（`2.08/1.716=1.212`） |
| 轮半径 | 旧表现 `0.41 m`（`torus(.315,.095)`）；滚动积分用 `0.40 m` | `0.39 m` | 比旧表现小 `0.02 m`，比滚动积分小 `0.01 m` |
| 轮距（轮胎中心） | `±0.83 m`，`1.66 m` | 轮胎中心 `±0.5525 m`，`1.105 m`（pivot `±0.39`＋网格外偏 `0.1625`） | 窄 `0.555 m` |
| 车宽 | 碰撞半宽 `0.91 m`（`circuit.js:31`，全宽 `1.82 m`） | `1.69 m`（`±0.845`） | 外观窄 `0.13 m` |
| 车长 | 碰撞半长 `1.57 m`（全 `3.14 m`） | `3.315 m` | 外观长 `0.175 m` |

当前旧车是**视觉轮位与物理轴位对齐**的（`-1.02/+1.06` 与 `config` 完全一致，轴距都是 `2.08 m`）。
标准件换成自己的 pivot 后，视觉轮距/轴距都比物理短：车会看起来绕一个更短的轴距转向，
前后轴处力作用点比可见轮胎分别前移 `0.202 m`、后移 `0.162 m`。这是**外观与物理的准确差异**；
本卡没有改 `config.frontAxle/rearAxle`、`CAR_HALF_S/L` 或镜头去迁就它，也不建议这样做。

**“直接替换后轮不贴地”的来源**：标准件自己的四轮触地点就是 `y≈0`（§3）。不贴地只会发生在
把两套变换混用的时候：

- 沿用当前轮位 `y=0.41`、却用标准轮半径 `0.39` → 触地 `+0.02 m`（悬空 2 cm）；
- 沿用标准 pivot `y=0.39`、却用当前轮半径 `0.41` → 触地 `-0.02 m`（入地 2 cm）；
- 沿用当前 `x=-1.02/+1.06、z=±0.83` 而车身用标准件 → 轮拱、轮距与车身都不对；
- 标准件按自己的 pivot 摆放 → 四轮贴地，但轴距/轮距与物理不一致（上表）。

## 5. 准确不兼容清单（本卡实际测到）

1. **轴距**：`1.716 m`（外观）vs `2.08 m`（物理），差 `0.364 m`。
2. **轮距**：轮胎中心 `1.105 m` vs 旧表现 `1.66 m`，差 `0.555 m`；车身宽 `1.69 m` vs 碰撞宽 `1.82 m`。
3. **轮半径与滚动积分**：轮面半径 `0.39 m`；`handling.js` 仍用 `r=0.4 m` 积分 `wheelSpin`，
   因此标准轮每米多转约 `2.56%`（旧表现 `0.41 m` 则少转约 `2.44%`）。这是既有近似，不是标准件新引入。
4. **转向轴不在轮胎中心**：pivot 在轮胎内侧 `0.1625 m`；`poseCar` 绕 pivot 做 `ry(-steer)`，
   本夹具 `2.37°` 时触地点横移 `6.7 mm`，低速最大锁角时约 `78 mm`；旧 `racer.js` 绕轮心转，无此横移。
5. **`roll` 的取源不同**：`racer.js` 用归一化 `player.steering`（−1…1），`steer` 用弧度
   `player.roadSteer`；两者不能互换。
6. **车身轮廓**：标准件是封闭座舱、高 `1.43 m`、无驾驶员；旧车含可见驾驶员（头部约 `1.9 m`）与尾翼。
   追尾机位下的遮挡、辨识度与屏幕占比（原设计目标 17–22%）均未验。
7. **材质**：标准件是线性 sRGB 顶点色，PBR roughness 只留在 GLB 元数据；当前 `render-three.js`
   仍走 Lambert／Toon，不消费 roughness。CPU 路径只验证了 `sourceData`／`sourceIndices` 可被
   `Mesh` 接收，没有创建 WebGLRenderer，因此**没有画面证据**。
